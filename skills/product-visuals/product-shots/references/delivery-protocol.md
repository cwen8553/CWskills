# 交付清单与局部修改

## 项目结构建议

```text
project/
  config/              # 私有品牌与项目配置
  sources/             # 原始证据，不自动对外打包
  working/             # 排版源、提示词、证据记录
  exports/             # 当前可交付文件
  history/             # 被替换与淘汰版本，不混入 exports
```

品牌授权、产品资料、实拍、实测表和证据文件由用户在自己的项目保存。通用 Skill 不包含客户媒体。输出范围取 config.deliverables；不为单模块修改强制交付整套新图。

## 清单

使用 [output-schema.json](../assets/output-schema.json) 记录项目 ID、版本和产物。状态为 candidate、checked、user_approved 或 rejected；checked 必须对应实际视觉检查记录，user_approved 必须对应真实用户确认。没有实际确认不能替用户批准。

每项记录角色、颜色、视角、项目内相对路径、图片真实像素、SHA-256、上游输入/模块 ID 和具体检查。文件被覆盖后旧检查失效，重新计算校验与检查。不要把模型自评数字当验收。

## 局部变更闭环

1. 列出受影响模块及依赖它的桌面图、手机图、整页、HTML 预览和压缩包。
2. 仅更新受影响部分；保留不变模块的哈希用于对照。
3. 排版源与导出同步，确保链接指向当前文件；从压缩包解开核对所含文件和清单，而非只检查 ZIP 存在。
4. 打开最终整页和受影响模块，检查手机效果与新旧接缝。
5. 交付本次有效文件和未完成项。发布、后台保存或上架如被授权，还需在目标端重新读取/查看结果。

内部客户名称、项目备注、生成日期、缺陷列表或审查脚注不默认放进消费者页面。必要的购买条件与真实限制保留在相应内容位置。
